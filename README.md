# Agile API

A REST API in Java for organizing tasks and activities, with optional synchronization with Google Calendar.

## About the project

Agile API works as the backend of an activity planner. It lets you register tasks with a title, description, due date and priority, and track the progress of each one over time (pending, in progress or completed). Since it is a REST API, it can be consumed by any client: a web front-end, a mobile app or tools like Postman.

As an extra feature, the API can be integrated with Google Calendar. When this integration is active, each task becomes an event in a dedicated calendar, with a color that shows its status, and the event follows the changes made to the task.

I built this project as a personal study and portfolio project, focusing on layered architecture, the use of DTOs, error handling and integration with an external service.

## Technologies

- **Java 25**
- **Spring Boot 4.1** (Spring Web MVC, Spring Data JPA and Bean Validation)
- **Hibernate**, through Spring Data JPA
- **H2 Database**, an in-memory database
- **MapStruct**, for converting between entities and DTOs
- **Lombok**, to reduce boilerplate code
- **Maven**, with Maven Wrapper
- **Google Calendar API** and **Google Auth Library**, authenticating with a Service Account

## Features

- Full CRUD for tasks
- Validation of the data received in requests
- Initial status (`PENDENTE`) and creation date set automatically by the API
- Standardized error response when a task is not found
- Optional synchronization with Google Calendar: creating, updating and removing events

## Architecture

The project follows a layered architecture:

```
src/main/java/com/agile/agileAPI
├── controller     # REST endpoints (TaskController)
├── servicos       # business rules (TaskService) and error handling
├── DTO            # input and output objects, and the mapper (TaskMapper)
├── entidades      # Task entity and the Status and Prioridade enums
├── repositorios   # database access (TaskRepository)
├── integracoes    # Google Calendar integration
└── excecoes       # application exceptions
```

The controller receives the HTTP requests and passes the data to the service. The service applies the business rules, converts the DTOs into the `Task` entity with the mapper, saves the data through the repository and, when the integration is active, notifies Google Calendar.

The entity is never exposed directly: the API's input and output use DTOs, implemented as Java `records`.

## Endpoints

Base URL: `http://localhost:8080/api/tasks`

| Method | Route | Description | Response |
|---|---|---|---|
| POST | `/api/tasks` | Creates a task | `201 Created` |
| GET | `/api/tasks` | Lists all tasks | `200 OK` |
| GET | `/api/tasks/{id}` | Finds a task by id | `200 OK` |
| PUT | `/api/tasks/{id}` | Updates a task | `200 OK` |
| DELETE | `/api/tasks/{id}` | Removes a task | `204 No Content` |

Accepted values for the enum fields:

- `prioridade`: `ALTA`, `MEDIA`, `BAIXA`
- `status`: `PENDENTE`, `EM_PROGRESSO`, `CONCLUIDA`

### Creating a task

`POST /api/tasks`

```json
{
  "titulo": "Estudar Spring Boot",
  "descricao": "Revisar o CRUD da API",
  "dataLimite": "2026-12-12",
  "prioridade": "ALTA"
}
```

The `titulo`, `dataLimite` and `prioridade` fields are required, and `descricao` is optional. The response includes the fields generated by the API:

```json
{
  "id": 1,
  "titulo": "Estudar Spring Boot",
  "descricao": "Revisar o CRUD da API",
  "dataLimite": "2026-12-12",
  "prioridade": "ALTA",
  "status": "PENDENTE",
  "dataCriacao": "2026-11-12"
}
```

### Updating a task

`PUT /api/tasks/{id}`

When updating, all fields are sent, including `status`:

```json
{
  "titulo": "Estudar Spring Boot",
  "descricao": "Revisar o CRUD da API",
  "dataLimite": "2026-12-12",
  "prioridade": "ALTA",
  "status": "EM_PROGRESSO"
}
```

### Errors

When a task is not found, the API responds with `404 Not Found`:

```json
{
  "mensagem": "Task não encontrada",
  "status": 404,
  "timeStamp": "2026-11-12T10:30:00"
}
```

Requests with invalid data, such as a blank title, return `400 Bad Request`.

## Google Calendar integration

### How it works

- When a task is **created**, the API creates an all-day event on the `dataLimite` date, with the title in the format `[PRIORITY] title` and the status in the description.
- The event's **color** shows the status: red for `PENDENTE`, yellow for `EM_PROGRESSO` and green for `CONCLUIDA`.
- When the task is **updated**, the event is updated. If the task doesn't have an event yet, it is created at that moment.
- When the task is **removed**, the event is removed as well.

The API stores the id of the event created in Google (`googleEventId`) in the task, so it can find the event later. If the communication with Google fails, the operation in the API still goes through normally, and the failure is logged as a warning.

### Authentication

The integration uses a Google Cloud **Service Account**, an account that belongs to the application rather than to a user. Because of that, it doesn't require a login screen. The Service Account only has access to the calendar that was shared with it.

### Implementation

The integration is defined by the `IntegracaoCalendario` interface, which has two implementations:

- `GoogleCalendarioService`: communicates with the Google Calendar API.
- `CalendarioDesativado`: does nothing.

The implementation in use is chosen by the `agile.google-calendar.enabled` property. By default, the integration is disabled, so that anyone can run the project without Google credentials.

## Running the project

### Prerequisites

- JDK 25

Installing Maven is not necessary, since the project uses the Maven Wrapper.

### Running the API

```bash
git clone https://github.com/telmelo/agile.git
cd agile
./mvnw spring-boot:run
```

On Windows, use `mvnw.cmd spring-boot:run`.

The API will be available at `http://localhost:8080`, with the Google integration disabled.

The H2 database console can be accessed at `http://localhost:8080/h2-console`, with the settings below. Since the database is in memory, the data is lost whenever the application restarts.

- **JDBC URL:** `jdbc:h2:mem:agendadb`
- **User:** `sa`
- **Password:** leave it blank

To run the tests:

```bash
./mvnw test
```

### Enabling the Google Calendar integration

1. In the [Google Cloud Console](https://console.cloud.google.com/), create a project and enable the **Google Calendar API**.
2. Create a **Service Account** and generate a key in JSON format. Keep the file outside the project folder.
3. In Google Calendar, create a new calendar (for example, "Agile") and share it with the Service Account's email, with the **"Make changes to events"** permission. In the calendar settings, copy the **Calendar ID**.
4. Create the file `src/main/resources/application-local.properties`:

   ```properties
   agile.google-calendar.enabled=true
   agile.google-calendar.calendar-id=YOUR_ID@group.calendar.google.com
   ```

5. Run the application with the `local` profile, providing the path to the key:

   ```bash
   SPRING_PROFILES_ACTIVE=local \
   GOOGLE_APPLICATION_CREDENTIALS=/path/to/the/key.json \
   ./mvnw spring-boot:run
   ```

The `application-local.properties` file and the Service Account keys are listed in `.gitignore`. Never commit credentials to the repository.

## Things to take notice of

- It is worth noting that, at least for now, the integration via Google Calendar is one-way: this means that changes made directly made in the Calendar interface are not sent to the API
- For now, user authentication isn't avaiable. Its currently being thought of implementing it through OAuth2
